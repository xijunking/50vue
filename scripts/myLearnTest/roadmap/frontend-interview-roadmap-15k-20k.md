# 前端面试复习基调文档（15K-20K 目标）

这份文档不是知识点清单，而是后续复习的“方向说明书”。

目标是帮助自己在准备 `15K-20K` 的前端开发岗位时，先建立正确预期、明确复习重点、控制投入顺序，避免陷入“知识点越看越多，但不知道该怎么准备”的状态。

---

## 1. 先定目标：这个价位的前端岗，通常在看什么

对 `15K-20K` 的前端岗位来说，面试官一般不是只看“会不会写页面”，也不会按大厂超深基础题的标准来全面拷打。

更常见的考察重点是：

1. 基础是否扎实，尤其是 `HTML / CSS / JavaScript / ES6+`
2. 是否真正做过业务，有没有完整的页面、列表、表单、权限、接口联调、状态管理经验
3. 对 `Vue` 或 `React` 是否有比较顺的理解，而不是只会背 API
4. 能不能把异步、状态、组件通信、性能优化这些常见问题讲明白
5. 简历上的项目是不是自己做过，能不能讲出“为什么这么设计”
6. 是否有一定的工程化意识，比如构建、规范、调试、联调、发布、排查问题
7. 如果岗位偏跨端或客户端，是否理解 `RN / uni-app`、生命周期、缓存、系统 API、线程这些概念

这意味着：

`15K-20K` 更像是在筛选“有基础、有项目经验、能独立做事、表达清楚的人”，而不是在筛选算法竞赛型选手。

---

## 2. 后续复习的总原则

后续复习不要再走“见一个补一个”的散点模式，建议统一遵循下面这 6 条原则。

### 2.1 先抓高频主线，不先追冷门细节

优先复习：

- `JavaScript` 核心机制
- `Vue / React` 核心思路
- 浏览器与网络基础
- 工程化与项目经验
- 移动端 / 跨端相关经验

先不要把大量时间放在：

- 很偏门的底层冷知识
- 很少面到的算法题型
- 过深的源码细节
- 记忆型八股的边角点

### 2.2 复习目标不是“全会”，而是“主干清楚、表达顺”

对这个价位来说，最有价值的是：

- 你知道大框架怎么串起来
- 你能把常见问题说明白
- 你能结合项目讲出真实取舍

而不是：

- 每个概念都背到百科全书程度

### 2.3 每个知识点都要回到“业务里怎么用”

例如复习 `Promise` 时，不只背定义，而是要能说：

- 为什么接口请求常配合 `async/await`
- 为什么状态更新后界面会变
- 为什么有些异步回调回来时组件已经销毁

例如复习状态管理时，不只背局部和全局，而是要能说：

- 登录态为什么适合放全局
- 弹窗开关为什么适合放局部
- 筛选条件什么时候需要持久化

### 2.4 项目表达能力，和技术知识同样重要

这个阶段的面试里，很多候选人不是“不会”，而是“讲不清”。

所以后续复习必须带上两条线：

1. 技术知识复习
2. 项目表达训练

### 2.5 先建立自己的答题框架，再补细节

后面复习每个主题时，都尽量按这个结构准备：

1. 这个东西是什么
2. 它解决什么问题
3. 它在项目里怎么用
4. 常见问题是什么
5. 如果让我优化，我会怎么做

### 2.6 不追求“全栈式大而全”，而是先做“前端主战场可信”

对当前目标来说，最重要的是：

- 前端主线要稳
- 跨端经验要能讲
- 客户端理解要够用

不需要强行把自己包装成：

- 深度后端
- 深度算法工程师
- 深度底层系统工程师

## 3. 你的个人优势，后续复习要怎么利用

从目前聊天内容看，你的复习不是从零开始，而是已经有一些不错的积累点：

1. 有 `Vue / React` 相关认知
2. 接触过 `RN / uni-app`
3. 理解部分生命周期、缓存、状态、系统 API
4. 还接触过蓝牙打印这类偏客户端能力

这其实是一个不错的组合，因为很多普通前端候选人只停留在纯页面层。

所以你的后续复习，不应该把这些经验“抹平”，而是应该把它们变成亮点：

### 3.1 主定位还是前端开发

主线还是：

- `JavaScript`
- `Vue / React`
- 浏览器 / 网络 / 工程化
- 页面和业务开发能力

### 3.2 跨端和客户端经验作为加分项

你可以把以下内容作为区别于普通前端候选人的补充亮点：

- `RN / uni-app` 的项目经验
- 生命周期和缓存理解
- 调系统 API 的经验
- 蓝牙打印等设备联动经验
- 对线程、性能、异步回调时机的基本理解

这类内容不一定每一轮都深问，但一旦岗位有移动端、H5、Hybrid、跨端诉求，它会很加分。

## 4. 面试复习的优先级分层

建议把后续复习内容分成 `A / B / C` 三层。

### 4.1 A 层：必须优先拿下

这是 `15K-20K` 前端岗最核心的得分区。

#### JavaScript 基础

- 数据类型、作用域、闭包、原型链
- `this`、箭头函数、构造函数
- 同步 / 异步
- 事件循环
- `Promise`
- `async/await`
- 深浅拷贝
- 防抖节流
- 常见数组方法

要求不是只会背，而是：

- 能解释
- 能举例
- 能和实际业务联系起来

#### 浏览器与网络

- 浏览器输入 URL 后发生了什么
- `HTTP / HTTPS`
- 常见状态码
- 缓存机制
- 跨域
- Cookie / localStorage / sessionStorage
- 从接口请求到页面更新的链路

#### Vue 或 React 核心

至少有一个框架要讲顺，另一个要有基本认知。

重点包括：

- 组件化思路
- props / state
- 组件通信
- 生命周期
- 响应式 / 渲染机制
- 列表渲染
- 条件渲染
- 表单处理
- hooks 或 composition API

#### 项目经验

这部分很关键，至少要准备好：

- 2 个能讲 10 分钟以上的项目
- 每个项目的背景、职责、难点、方案、结果
- 自己做了什么，而不是团队做了什么
- 遇到过什么问题，如何排查和解决

### 4.2 B 层：有明显加分，但不用一开始钻太深

#### 工程化

- `npm / pnpm`
- `webpack / vite` 基本理解
- 打包、构建、环境变量
- 代码规范、提交规范
- 常见调试方式

#### 性能优化

- 首屏优化
- 减少重复渲染
- 图片优化
- 列表优化
- 缓存策略
- 接口并发与懒加载

#### 状态管理

- 局部状态、全局状态
- 持久化状态
- 派生状态
- 状态边界怎么划分

#### 移动端 / 跨端

- `RN / uni-app` 的基本架构理解
- 页面生命周期
- 缓存
- 系统 API
- 蓝牙打印等设备能力接入

### 4.3 C 层：知道即可，按时间决定是否深挖

- 框架源码级原理
- 更底层的浏览器渲染实现细节
- 很深的计算机网络细节
- 很深的线程 / 并发底层机制
- 高难算法题

这些不是没价值，而是当前阶段不一定是最优投入。

## 5. 后续复习的主题主线

后续建议围绕下面 7 条主线复习，而不是按碎片知识点乱跳。

### 5.1 主线一：JavaScript 核心机制

目标：

- 把 `JS` 从“会写”提升到“能说清楚”

重点：

- 作用域、闭包、原型链
- `this`
- 构造函数与普通函数
- 事件循环
- `Promise`
- `async/await`
- 常见手写题思路

复习标准：

- 能解释原理
- 能写简单例子
- 能和接口请求、页面更新联系起来

### 5.2 主线二：页面渲染与数据流

目标：

- 建立“数据如何驱动界面”的统一认知

重点：

- 原生 JS 如何更新 DOM
- Vue / React 的状态驱动视图
- 局部状态、全局状态、派生状态
- 初始化、持久化、更新时机

复习标准：

- 能从数据流角度讲业务开发
- 能解释为什么状态设计会影响可维护性

### 5.3 主线三：Vue / React 框架能力

目标：

- 至少有一个框架能讲得很稳

重点：

- 生命周期 / hooks
- 组件通信
- 响应式或渲染更新机制
- 常见业务写法
- 常见坑和优化点

复习标准：

- 不只会背 API
- 能结合项目说“为什么这么写”

### 5.4 主线四：浏览器、网络与缓存

目标：

- 把接口请求、页面加载、缓存策略串起来

重点：

- 从输入 URL 到页面展示
- 请求响应过程
- 跨域
- 缓存
- 存储机制

复习标准：

- 能把接口联调、登录态、缓存命中这些常见业务问题讲顺

### 5.5 主线五：工程化与协作

目标：

- 让面试官相信你能进入团队正常协作

重点：

- 构建工具基础理解
- 环境配置
- 包管理
- 发布流程
- 调试与排查
- Git 基本协作

复习标准：

- 不需要源码级，但要知道日常开发里怎么用、为什么用

### 5.6 主线六：性能与体验优化

目标：

- 能回答“你做过哪些优化”

重点：

- 页面加载性能
- 列表性能
- 请求优化
- 渲染优化
- 缓存优化

复习标准：

- 至少准备 3 到 5 个自己项目里真实发生过的优化点

### 5.7 主线七：跨端与客户端加分项

目标：

- 把你的 `RN / uni-app / 蓝牙打印` 经验变成亮点

重点：

- 页面生命周期
- 缓存
- 系统 API
- 蓝牙连接与打印流程
- UI、JS、Native 的协作理解
- 线程的基本分工认知

复习标准：

- 不用讲得特别底层
- 但要能证明你不只是做纯网页

## 6. 面试表达的基调

后面准备面试时，答题风格也要有一个统一基调。

### 6.1 少背定义，多讲链路

例如不要只说：

`Promise 是异步编程解决方案。`

更好的说法是：

`在前端里 Promise 主要是为了更清晰地处理异步结果，比如接口请求回来后再更新状态。后面 async/await 其实也是基于 Promise，只是让代码读起来更像同步流程。`

### 6.2 少空谈原理，多贴业务场景

例如不要只说：

`Vue 是响应式的。`

更好的说法是：

`比如页面初始化时先请求接口，拿到数据后更新 ref 或 reactive，对应模板会自动更新，不需要手动去改 DOM。`

### 6.3 少说“我知道一点”，多说“我做过什么”

例如：

- 我做过哪些模块
- 我解决过什么问题
- 我是怎么排查的
- 为什么最后这样取舍

### 6.4 对不会的内容，不要硬扛

如果某一块不够深，可以这样回答：

- 先说自己已知的主干
- 再说明自己在项目中的使用范围
- 最后坦诚这部分还没有系统深挖

这种答法比硬编更稳。

## 7. 15K-20K 岗位下，什么算“够用的深度”

后续复习时，很多时候不是“懂不懂”，而是“不知道该学到多深”。

这里给自己一个简单标准。

### 7.1 JavaScript

目标深度：

- 能解释常见机制
- 能做基础手写题
- 能结合实际业务举例

不必当前就强求：

- 特别偏底层的规范级细节

### 7.2 Vue / React

目标深度：

- 组件开发熟练
- 生命周期 / hooks 能讲清
- 状态、通信、渲染更新能说明白
- 常见性能问题有经验

不必当前就强求：

- 大量源码级实现细节

### 7.3 工程化

目标深度：

- 知道打包构建是怎么服务开发的
- 知道常见命令、配置、环境变量、调试流程

不必当前就强求：

- 自己从零实现一个构建器

### 7.4 跨端 / 客户端

目标深度：

- 能说明白页面、生命周期、缓存、系统 API、异步回调链路
- 能结合蓝牙打印这类场景讲出真实问题

不必当前就强求：

- 深入到系统内核或驱动层

## 8. 后续复习安排建议

后续复习尽量按照“主线 + 输出”的方式推进。

### 8.1 第一阶段：搭骨架

目标：

- 先把高频主线全过一遍

内容：

- `JavaScript`
- `Vue / React`
- 浏览器 / 网络
- 状态管理
- 工程化基础

输出：

- 每个主题整理自己的简版笔记
- 每个主题准备 3 到 5 个常见面试问答

### 8.2 第二阶段：连项目

目标：

- 把知识点和自己的项目经验绑定

内容：

- 接口联调
- 权限控制
- 列表、表单、缓存
- 性能优化
- 跨端能力

输出：

- 2 到 3 个项目故事模板
- 每个项目准备“难点、方案、结果、反思”

### 8.3 第三阶段：查漏补缺

目标：

- 补面试常见短板

内容：

- 手写题
- 高频八股
- 表达不顺的主题
- 自己答不出来的问题

输出：

- 高频题清单
- 易错题回顾
- 自己的答题模板

## 9. 一个建议坚持的复习习惯

为了让后面的复习更有效，建议始终保持下面这个习惯：

### 每复习一个主题，都写下这 4 个问题

1. 这个知识点是什么
2. 它解决什么问题
3. 它在我的项目里出现在哪
4. 面试官如果追问，我下一层该怎么回答

这会逼着自己从“知道”走向“会说、会用、会展开”。

---

## 10. 当前阶段最重要的一句话

当前目标不是把自己准备成“全能型技术百科”，而是：

`把前端主线打稳，把已有项目经验讲透，把跨端能力转成加分项。`

对 `15K-20K` 的前端岗位来说，这条路线通常比“哪里不会补哪里、到处零散发力”更有效。

---

## 11. 这份文档接下来的使用方式

后续每次复习一个大主题时，都回到这份文档看三件事：

1. 这个主题属于哪条主线
2. 它在 `A / B / C` 优先级里排第几层
3. 我要把它复习成“能做题”，还是“能讲项目”，还是“两者都要”

如果发现自己又开始焦虑“知识点太多”，就回到这几个判断标准：

- 这是不是高频
- 这和目标岗位匹不匹配
- 这能不能和项目经验连接起来
- 现在学它的投入产出比高不高

只要这几个问题始终清楚，后续复习就不会跑偏。
